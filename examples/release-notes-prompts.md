# Release Notes Prompt Examples

## 1. Draft release notes
> Turn these verified changes [commits or change list] into concise release notes for [audience]. Group by Added, Changed, Fixed, and Removed where appropriate. Do not claim features or fixes that are not in the input.

## 2. Identify breaking changes
> Review these changes [diff/spec] for potential compatibility impacts. Separate confirmed breaking changes from risks that need verification, and identify affected users or integrations.

## 3. Create a migration checklist
> Based on these documented changes [source], prepare a migration checklist with prerequisites, actions, validation steps, rollback considerations, and unresolved questions. Do not invent commands or version requirements.
