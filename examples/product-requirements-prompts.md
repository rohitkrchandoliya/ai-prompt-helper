# Product Requirements Prompt Examples

## 1. Draft user stories
> Based on this product context [context], draft user stories that identify user, need, and outcome. Do not add scope not supported by the context.

## 2. Write acceptance criteria
> Convert this requirement [requirement] into testable acceptance criteria, including normal, boundary, and failure cases. Use clear observable outcomes and flag unresolved policy choices.

## 3. Find requirement gaps
> Review these requirements [requirements] for ambiguity, contradictions, missing permissions, error states, and accessibility needs. Ask targeted questions before proposing assumptions.
