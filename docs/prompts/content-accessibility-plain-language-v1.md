# Content accessibility and plain-language review

## Purpose
Make product content easier to understand while preserving meaning and accessibility.

## Input checklist
- [ ] Source content
- [ ] audience
- [ ] task
- [ ] terminology
- [ ] reading context
- [ ] accessibility requirements
- [ ] localization constraints.

## Prompt
> Act as a careful senior practitioner. Base findings on supplied evidence, separate assumptions from verified facts, and make the process repeatable. Identify jargon, ambiguous instructions, unexplained acronyms, inconsistent terminology, and cognitive load. Offer concise revisions while preserving necessary caveats and ensuring link text and instructions remain meaningful out of context. Highlight high-impact unknowns and explain how to resolve them.

## Required output
- Issue list
- Revised copy
- Rationale
- Terminology notes
- Accessibility checks
- User validation questions.

## Guardrails
- Do not remove critical warnings or alter legal, medical, or safety meaning for brevity.
- Include explicit validation steps and evidence needed for sign-off.
- Avoid unsupported certainty and generic recommendations.
