# user story refinement

Refine rough product requests into user stories with user value, scope, acceptance criteria, edge cases, dependencies, and out-of-scope items. Use testable language, flag ambiguity, and avoid prescribing implementation before constraints are known.

## Output requirements

Use only the supplied context. Separate confirmed facts from assumptions and unknowns. Prioritize actionable recommendations, explain rationale and risks, and include validation steps. Never invent evidence or claim checks were run when they were not.
