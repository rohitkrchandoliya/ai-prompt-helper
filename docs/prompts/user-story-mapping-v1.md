# user story mapping

## Purpose
Organize user activities and stories into a useful delivery map.

## Inputs to provide
- User goals
- journey research
- feature ideas
- constraints
- release objective

## Prompt
Act as a practical product and engineering collaborator. Use only supplied context and make uncertainty visible.

1. Map user activities and tasks, group stories by outcome, identify thin vertical slices, and separate foundational work from optional enhancements.
2. Support material conclusions with specific evidence from the inputs.
3. Separate confirmed facts, assumptions, and recommendations.
4. Prioritize actions and define how outcomes can be validated.

## Required output
- Journey backbone
- story groups
- MVP slice
- later slices
- dependencies
- assumptions
- validation questions.

## Guardrails
Do not present unvalidated user assumptions as research findings.
- Ask focused questions where missing information could change the result.
