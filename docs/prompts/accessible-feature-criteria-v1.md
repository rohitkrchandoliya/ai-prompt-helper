# accessible feature acceptance criteria

## Purpose
Translate feature requirements into testable accessibility acceptance criteria.

## Inputs to provide
- Feature brief
- target platforms
- user interactions
- applicable standards
- design notes

## Prompt
Work as an evidence-led practitioner. Use the provided material as the source of truth and make missing context explicit.

1. Cover keyboard operation, semantics, names/labels, focus behavior, errors, zoom/reflow, contrast where relevant, and nonvisual feedback.
2. Tie each material conclusion to specific supplied evidence.
3. Distinguish observed facts, hypotheses, and recommendations.
4. Prioritize practical next steps and define how success will be verified.

## Required output
- Given/when/then criteria
- test method
- expected behavior
- platform-specific notes
- unresolved design questions.

## Guardrails
Do not assert compliance solely from written criteria; ensure criteria can be tested by humans and suitable tools.
- Ask concise clarifying questions when a missing input would change the recommendation.
