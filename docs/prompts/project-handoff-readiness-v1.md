# Project handoff readiness review

## Purpose
Assess whether a project can be handed to a new owner with enough context to continue effectively.

## Inputs
- Current scope and status
- Key decisions and open questions
- Environment and access prerequisites
- Known risks and dependencies
- Ownership and support expectations

## Prompt
Review the supplied project materials as an experienced delivery lead. Identify missing context, undocumented decisions, unclear ownership, blocked dependencies, and steps needed for a new owner to reproduce the current state. Separate confirmed facts from assumptions and propose a prioritized handoff plan.

## Required output
- Readiness scorecard with rationale
- Missing documentation and access checklist
- Open decisions and risks
- Knowledge-transfer agenda
- First-week action plan
- Completion acceptance criteria

## Guardrails
- Do not invent access rights, owners, dates, or project status.
- Never include credentials or secrets in handoff documents.
- Mark unresolved items clearly and assign ownership only when confirmed.
