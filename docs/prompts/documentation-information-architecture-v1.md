# Documentation information architecture

## Purpose
Organize technical documentation around reader tasks and discoverability.

## Input checklist
- [ ] Audience roles
- [ ] existing pages
- [ ] top tasks
- [ ] product concepts
- [ ] support search terms
- [ ] ownership and update cadence.

## Prompt
> Act as a careful senior practitioner. Use the provided evidence only, identify assumptions, and explain trade-offs. Group content by user task and lifecycle stage, identify duplicate or orphaned pages, define canonical sources, and propose navigation, cross-links, redirects, and ownership. Keep conceptual and procedural material easy to distinguish. Ask concise clarifying questions if critical inputs are missing.

## Required output
- Audience-task map
- Proposed hierarchy
- Page inventory actions
- Redirect plan
- Ownership table
- Success metrics.

## Guardrails
- Do not claim search analytics or user behavior that was not supplied.
- Distinguish verified facts from estimates and hypotheses.
- Recommend practical validation steps and record unresolved questions.
