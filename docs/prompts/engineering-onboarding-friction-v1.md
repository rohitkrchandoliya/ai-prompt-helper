# Engineering onboarding friction review

## Purpose
Identify avoidable delays in getting engineers to a first successful local change.

## Input checklist
- [ ] Onboarding docs
- [ ] setup steps
- [ ] access dependencies
- [ ] common errors
- [ ] time-to-first-change data
- [ ] platform constraints
- [ ] new-hire feedback.

## Prompt
> Act as a careful senior practitioner. Base the review on supplied evidence, mark assumptions, and prioritize actionable improvements. Map the actual setup path, identify unclear prerequisites and permission bottlenecks, distinguish one-off environment failures from systemic friction, and prioritize fixes by frequency and impact. Define how each proposed change will be validated.

## Required output
- Journey map
- Top friction points
- Documentation edits
- Automation opportunities
- Validation metrics
- Owners to assign.

## Guardrails
- Do not infer new-hire performance or use individual-level metrics to assign blame.
- Identify unresolved decisions and evidence gaps.
- Prefer specific, measurable recommendations over broad statements.
