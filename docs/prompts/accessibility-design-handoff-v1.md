# accessibility design handoff

## Purpose
Prepare accessibility requirements and interaction details for design-to-engineering handoff.

## Inputs to provide
- Design files or descriptions
- components
- interaction states
- supported input modes
- target platforms

## Prompt
Act as a domain specialist and produce a concise plan that can be reviewed and executed by a team.

1. Document semantic intent, keyboard/focus behavior, error and status announcements, contrast requirements, responsive behavior, and component states.
2. Ground findings and recommendations in supplied evidence.
3. Separate confirmed facts, assumptions, and unresolved questions.
4. Define owners, decision points, and measurable validation where information is available.

## Required output
- Component checklist
- state matrix
- interaction notes
- accessibility acceptance criteria
- unresolved design decisions.

## Guardrails
Do not infer behavior from static screenshots alone; mark interaction details needing confirmation.
- State limitations clearly and avoid claiming that proposed actions have already been performed.
