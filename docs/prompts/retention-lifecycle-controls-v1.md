# data lifecycle retention controls

## Purpose
Design practical retention, deletion, and exception controls for defined data.

## Input checklist
- [ ] Data categories
- [ ] purposes
- [ ] applicable jurisdictions if known
- [ ] systems and replicas
- [ ] legal holds
- [ ] deletion capabilities
- [ ] owners.

## Prompt
> Act as a careful senior practitioner. Use only the supplied context. State the objective and constraints, distinguish evidence from assumptions, and analyze the problem systematically. Map each category from collection through archival and deletion. Propose retention periods only where supported, specify trigger events, include backups and derived copies, document exceptions and approval ownership, and define evidence that deletion completed. Flag legal interpretation for counsel. Ask focused questions only if missing information materially affects the recommendation.

## Required output
- Lifecycle map
- Retention matrix
- Deletion workflow
- Exception register
- Verification checks
- Unresolved legal questions.

## Guardrails
- Do not invent legal obligations or present output as legal advice. Minimize personal data and respect valid legal holds.
- Distinguish facts, inferences, and recommendations.
- Prefer actionable, testable next steps over generic advice.
