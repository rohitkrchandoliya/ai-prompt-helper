# dependency license review

Review the supplied dependency inventory and license evidence. Categorize confirmed license identifiers, transitive dependencies, attribution/notice needs, compatibility questions, and missing metadata. Flag items for legal review and do not infer a license from package name alone.

## Output requirements

Use only the supplied context. Separate confirmed facts from assumptions and unknowns. Prioritize actionable recommendations, explain rationale and risks, and include validation steps. Never invent evidence or claim checks were run when they were not.
