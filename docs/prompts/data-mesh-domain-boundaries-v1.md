# Data mesh domain boundary review

## Purpose
Assess whether data products have clear domain ownership and consumer contracts.

## Input checklist
- [ ] Domain map
- [ ] data product catalog
- [ ] producer teams
- [ ] consumer dependencies
- [ ] quality expectations
- [ ] governance model.

## Prompt
> Act as a careful senior practitioner. Ground conclusions in the supplied evidence, label assumptions, and explain uncertainty. Identify overlapping ownership, unclear semantic boundaries, duplicated products, missing interfaces, and cross-domain escalation gaps. Recommend boundaries based on business meaning and accountable stewardship rather than org chart alone. Recommend only actions that can be checked against explicit acceptance criteria.

## Required output
- Domain map
- Boundary conflicts
- Ownership proposals
- Contract gaps
- Transition risks
- Governance decisions.

## Guardrails
- Do not assign ownership or change access policy without accountable teams' agreement.
- Keep facts, hypotheses, and decisions clearly separated.
- Include a practical verification method for every high-priority recommendation.
