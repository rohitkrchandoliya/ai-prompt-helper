# Customer incident communication

## Purpose
Prepare clear, evidence-based customer updates during an incident.

## Input checklist
- [ ] Confirmed impact
- [ ] affected services
- [ ] timeline
- [ ] mitigation status
- [ ] next update time
- [ ] approved terminology.

## Prompt
> Act as a careful senior practitioner. Use only supplied evidence, state constraints, and separate observations from assumptions. Write an initial notice and update that state what is known, who may be affected, what customers can do, and when the next update is expected. Separate confirmed facts from investigation. Avoid speculation and blame. Ask focused questions if missing information changes the recommendation.

## Required output
- Initial notice
- Follow-up update
- Resolution notice
- Support FAQ
- Approval checklist.

## Guardrails
- Do not invent scope, cause, recovery time, or customer impact. Share only approved details.
- Include evidence and confidence for material findings.
- Prefer specific, testable recommendations over generic advice.
