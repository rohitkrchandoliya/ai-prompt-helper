# Migration communication plan

## Purpose
Create clear communications for users affected by a product or platform migration.

## Input checklist
- [ ] What changes
- [ ] affected cohorts
- [ ] dates
- [ ] required user action
- [ ] downtime risks
- [ ] support channels
- [ ] rollback conditions.

## Prompt
> Act as a careful senior practitioner. Use only supplied information, identify assumptions and evidence gaps, and distinguish analysis from decisions. Segment audiences by impact, explain why and when the change happens, specify required actions and support routes, and provide reminders and escalation for non-migration. Keep dates and claims tied to confirmed plans. Request clarification where missing facts materially change the outcome.

## Required output
- Audience matrix
- Message sequence
- Draft notices
- FAQ topics
- Support readiness
- Approval checklist.

## Guardrails
- Do not invent dates, downtime, or guarantees. Avoid alarmist or misleading language.
- Make the reasoning traceable to provided evidence.
- Give recommendations measurable verification criteria where possible.
