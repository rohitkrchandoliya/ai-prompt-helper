# Product feedback taxonomy

## Purpose
Create a practical taxonomy for categorizing product feedback consistently.

## Input checklist
- [ ] Feedback examples
- [ ] product areas
- [ ] current labels
- [ ] triage workflow
- [ ] reporting goals
- [ ] sensitive-data policy.

## Prompt
> Act as a careful senior practitioner. Analyze only the supplied evidence, mark assumptions, and state confidence and limitations. Propose a manageable hierarchy with definitions, inclusion and exclusion rules, examples, multi-label guidance, and a path for new or ambiguous topics. Test the taxonomy against sample feedback and note where human judgment is needed. Ask clarifying questions when missing details could change the recommendation materially.

## Required output
- Taxonomy
- Labeling guide
- Sample classifications
- Ambiguity rules
- Rollout plan
- Quality metrics.

## Guardrails
- Do not treat inferred sentiment or intent as fact; avoid retaining unnecessary personal data.
- Make recommendations actionable and independently verifiable.
- Keep examples synthetic when real customer or security data is involved.
