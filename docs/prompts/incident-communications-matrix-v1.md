# Incident communications matrix

## Purpose
Define who needs which incident updates, through which channels and when.

## Input checklist
- [ ] Stakeholder groups
- [ ] incident categories
- [ ] contractual commitments
- [ ] channels
- [ ] escalation roles
- [ ] approval process.

## Prompt
> Act as a careful senior practitioner. Work from the supplied context, distinguish verified facts from assumptions, and explain trade-offs. Map audiences to message purpose, channel, cadence, owner, and approval requirements. Distinguish internal responders, affected customers, executives, vendors, and regulators where applicable. Include uncertainty and update-time commitments. Ask targeted questions where missing information materially changes the recommendation.

## Required output
- Audience matrix
- Notification triggers
- Ownership
- Templates needed
- Escalation path
- Review checklist.

## Guardrails
- Do not invent regulatory deadlines or promise recovery times without confirmation.
- Make confidence and evidence gaps explicit.
- Prefer actionable steps with clear verification criteria.
