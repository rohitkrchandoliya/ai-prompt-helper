# Accessible form error review

## Purpose
Improve form validation so errors are perceivable, understandable, and actionable.

## Input checklist
- [ ] Form fields
- [ ] validation rules
- [ ] error messages
- [ ] focus behavior
- [ ] screen-reader behavior
- [ ] design system
- [ ] supported platforms.

## Prompt
> Act as a careful senior practitioner. Base conclusions on supplied artifacts, separate facts from hypotheses, and identify material unknowns. Review labels, instructions, inline and summary errors, focus management, announcement behavior, correction guidance, and preservation of valid input. Cover client-side and server-side validation and non-color cues. Provide a concise rationale for each high-priority recommendation.

## Required output
- Issue list
- Revised copy
- Keyboard and screen-reader test cases
- Acceptance criteria
- Design recommendations.

## Guardrails
- Do not assume color or visual placement alone communicates errors.
- Include measurable verification steps and note any assumptions.
- Prefer prioritized, specific actions over generic advice.
