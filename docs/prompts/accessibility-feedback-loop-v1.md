# Accessibility feedback loop

## Purpose
Create a process for tracking and resolving accessibility barriers over time.

## Input checklist
- [ ] Feedback channels
- [ ] issue tracker
- [ ] product owners
- [ ] support data
- [ ] release process
- [ ] target criteria.

## Prompt
> Act as a careful senior practitioner. Work from the provided context, distinguish evidence from assumptions, and make trade-offs explicit. Define intake, severity, triage, reproduction, ownership, remediation, user communication, and regression prevention. Include feedback from disabled users, manual testing, and assistive technology coverage. Establish closure evidence and trend reviews. Identify any missing input that could change the recommendation.

## Required output
- Workflow
- Severity rubric
- Ownership model
- Tracking fields
- Regression checks
- Reporting cadence.

## Guardrails
- Do not treat automated scans as a substitute for testing with assistive technologies and users.
- Prefer measurable acceptance criteria and actionable follow-up.
- Do not claim a control or test exists unless evidence is provided.
