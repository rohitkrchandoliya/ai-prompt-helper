# Incident severity matrix

## Purpose
Define consistent incident severity levels and escalation triggers.

## Input checklist
- [ ] Service objectives
- [ ] user impact categories
- [ ] data sensitivity
- [ ] scope
- [ ] duration
- [ ] on-call model
- [ ] contractual commitments.

## Prompt
> Act as a careful senior practitioner. Use only the supplied evidence, distinguish facts from assumptions, and state the key trade-offs. Create severity levels with observable impact criteria, examples, escalation and communication expectations, and downgrade rules. Cover partial outages, degraded performance, security incidents, and uncertainty while avoiding conflicting definitions. Ask targeted questions if a missing detail materially affects the conclusion.

## Required output
- Severity matrix
- Examples
- Escalation map
- Reassessment cadence
- Communication triggers
- Governance notes.

## Guardrails
- Do not contradict binding response obligations. Label any proposed thresholds needing stakeholder approval.
- Give recommendations a clear rationale and validation method.
- Explicitly list unknowns and decision owners.
