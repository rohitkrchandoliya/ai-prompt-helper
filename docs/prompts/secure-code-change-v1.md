# secure code change planning

Plan a secure implementation for the described feature. Identify trust boundaries, input validation, authorization, data handling, error behavior, logging, tests, and threat cases. Prefer established project patterns, flag unknown requirements, and avoid unnecessary complexity.

## Output requirements

Use only the supplied context. Separate confirmed facts from assumptions and unknowns. Prioritize actionable recommendations, explain rationale and risks, and include validation steps. Never invent evidence or claim checks were run when they were not.
