# Accessibility Review Checklist

Use this checklist when changing forms, buttons, prompt results, history controls, or status messages.

- [ ] Every input has a clear, programmatically associated label.
- [ ] Interactive controls can be reached and operated with a keyboard.
- [ ] Keyboard focus is visible and follows a logical order.
- [ ] Buttons have names that describe their actions.
- [ ] Validation errors explain how to correct the problem.
- [ ] Success and error feedback is available to assistive technology where appropriate.
- [ ] Text and controls have sufficient contrast.
- [ ] The layout remains usable at browser zoom and on narrow screens.
- [ ] Removing or clearing history does not rely on color alone to communicate meaning.

This checklist is a review aid, not a substitute for testing with actual browsers and assistive technologies.
